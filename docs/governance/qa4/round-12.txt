### [P0-1] Claude Code registers none of the 29 skills, and both surface validators stay green

The ported skills never load as skills under Claude, even though AGENTS.md and ADR-005 promise four equivalent surfaces.

- **Where**: `agentic/manifest.yaml` (`surfaces.claude.layout.skills: skills`, `extension: .md`); `scripts/sync_agentic_adapters.py:369-372` (`target_path` → `.claude/skills/<name>.md`); the claim is at `.claude_context.md:25`.
- **Commands**:

  ```text
  $ ls .claude/skills | head -3 ; find .claude/skills -name SKILL.md | wc -l
  batch-inference.md
  ci-green-verify.md
  concept-drift-analysis.md
  0
  $ test -f .claude/skills/enterprise-audit/SKILL.md || echo absent
  absent
  $ grep -n 'is listed as a skill' .claude_context.md
  25:- A file under `.claude/skills/` is listed as a skill, but its body is a pointer — read `agentic/skills/<id>/SKILL.md` …
  $ uv run python scripts/sync_agentic_adapters.py --check
  [sync] OK — 74 artifacts, 4 surfaces, all current
  $ uv run python scripts/validate_agentic_surface.py --strict
  [agentic] OK — surface is coherent across every tool
  $ ls services/demand-forecast-serving/.claude/skills/batch-inference/ ; head -3 services/demand-forecast-serving/.claude/skills/batch-inference/SKILL.md
  SKILL.md
  ---
  name: batch-inference
  ```

- **Executed evidence from this Claude Code session**:
  - The harness's skill list for this repository contains exactly the 22 names in `.claude/commands/` (`qa`, `tests`, `release`, …). Each has the description `<!-- generated by scripts/sync_agentic_adapters.py — do not edit -->`, because the pointer's first line is an HTML comment and it has no front-matter.
  - It contains **none** of the 29 skill names. `enterprise-audit` was not invocable, and the prompt had anticipated exactly that.
  - Claude Code discovers project skills at `.claude/skills/<name>/SKILL.md`, with `name`/`description` front-matter.
- **Impact**:
  - The skills plane doesn't exist for Claude, including the STOP-mode `secret-breach-response`, whose `mode:` lives only in the canonical front-matter.
  - The four-surface parity claim (`AGENTS.md:400-403`: "a rule that binds under one tool binds under all of them"; ADR-005 "four-plane") is false for skills on this surface.
  - `.claude_context.md` tells agents the opposite of the truth.
  - `--check` and `--strict` verify only that pointer files exist and match the renderer, so the defect cannot turn them red.
- **§6 classification**: a **discipline failure, not inherited debt**. The base template, as rendered in this repository at `services/demand-forecast-serving/.claude/skills/<name>/SKILL.md`, already uses the correct layout with front-matter. The port flattened it.
- **Not verified**: whether `.cursor/skills/*.mdc` and `.codex/skills/*.md` have the same problem. Both are flat as well.
- **Fix**:
  - Render the Claude skills as `.claude/skills/<id>/SKILL.md` with `name:` and `description:` front-matter (description taken from the canonical `description`, plus its `mode`).
  - Add a `description:` front-matter to the `.claude/commands/*.md` pointers.
  - Add a V-check that fails when a surface's skill path doesn't match the tool's discovery layout.
  - Correct `.claude_context.md:25`.
  - Check the Cursor and Codex layouts against those tools' documentation before claiming parity for them.
