### [P2-1] agent-local's export check cannot see a subpackage, so a `core/policy/` package replaces the exported `policy.py` and the check reports OK

```text
scripts/export_llm_core.py:262
    return sorted(path.name for path in core.glob("*.py") if path.name not in expected)
(the same glob is in agent-local tests/test_core_is_exported.py:43)

$ mkdir core/policy && <policy.py with absolute imports, plus SHADOWED = True> > core/policy/__init__.py
$ python3 scripts/export_llm_core.py --dest /tmp/qa4-r13-al-copy --check     # ml-platform at f8400f7
[export] OK — /tmp/qa4-r13-al-copy/core matches an export of f8400f773d0b

$ python3 -c "import core, core.policy as p; print(p.__file__, getattr(p,'SHADOWED',False))"
/tmp/qa4-r13-al-copy/core/policy/__init__.py True
```

Python's `FileFinder` returns a package directory before a same-named `.py`. The exported `policy.py` is byte-identical and its hash matches, but it is never imported. The exporter's own docstring promises that a change in agent-local's `core/` fails. It does not for any subpackage (`core/ext/__init__.py` also gives `OK`, exit 0), nor for a `.pyi` or data file. This is R12-1 attacked with an edit neither party chose.

**Fix:** make `stray_modules` recurse and cover every entry, not only `*.py`. For example, flag any path under `core/` other than the twelve modules, `EXPORTED_FROM.json` and `__pycache__/`, and fail on any directory. Mirror the same rule in agent-local's `test_core_is_exported.py`. Add a test that creates `core/policy/__init__.py` and asserts `--check` exits 1.
