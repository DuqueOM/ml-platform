## 3. Findings, most severe first

### [P2-1] C6's link scan misses four equally valid forms of a link to a non-public DuqueOM repository

```text
scripts/check_doc_coherence.py:790   repo_link = re.compile(r"github\.com/([A-Za-z0-9_-]+)/([A-Za-z0-9_.-]+)")
scripts/check_doc_coherence.py:871   if owner != PRIVATE_ACCOUNT:          # case-sensitive; GitHub owners are not

$ echo "see https://github.com/OWNER/PRIVATE-REPO" > docs/_r14.md && uv run python scripts/check_doc_coherence.py --only C6
  FAIL [C6] docs/_r14.md links to non-public repository 'PRIVATE-REPO'          # control
https://github.com/OWNER/PRIVATE-REPO            ->  ok  [C6] 1389 files scanned …
git clone git@github.com:OWNER/PRIVATE-REPO.git  ->  ok  [C6] 1389 files scanned …
https://api.github.com/repos/OWNER/PRIVATE-REPO  ->  ok  [C6] 1389 files scanned …
https://raw.githubusercontent.com/OWNER/PRIVATE-REPO/main/x  ->  ok  [C6] 1389 files scanned …
```

GitHub treats `duqueom` and `DuqueOM` as the same owner, and the SSH, API and raw forms all disclose the repository name. The denylist half of C6 still catches the one known private name. This is the general half, which exists for "a repository nobody has thought to add to a denylist yet". A new mutation, **R14-C6-https-prefix-only** (require `https://` in front), also **survives** `tests/test_gate_scripts.py`. So no test pins the scheme-less form either, even though it is the form the pattern was written for.

**Fix:** compare owners case-insensitively. Widen the pattern to `(?:github\.com[/:]|api\.github\.com/repos/|raw\.githubusercontent\.com/)(owner)/(repo)`. Add one test per form, and a catalogue entry for each.

### [P2-2] C9 exempts copier's own shorthand for a GitHub source, and #100's comment stripping and its fence parsing hide real commands

```text
scripts/check_doc_coherence.py:957   source_is_local = re.search(r"\s(\.|\.\./|/)\S*", command) and "http" not in command
scripts/check_doc_coherence.py:920   line = re.sub(r"\s#.*$", "", line)
scripts/check_doc_coherence.py:886   _FENCE = re.compile(r"```[a-z]*\n(.*?)```", re.DOTALL)

$ uv run python scripts/check_doc_coherence.py --only C9      # one probe per run, each in a ```bash fence
copier copy https://github.com/DuqueOM/ml-service-template out          ->  FAIL [C9] … unpinned   (control)
copier copy gh:DuqueOM/ml-service-template ./services/x                  ->  ok  [C9] 13 … all pinned
copier copy gh:DuqueOM/ml-service-template /srv/x                        ->  ok  [C9] 13 … all pinned
echo 'step #1' && copier copy https://github.com/DuqueOM/ml-service-template out  ->  ok  [C9] …
```shell-session block, then a ```bash block holding the command   ->  ok  [C9] …
~~~bash fence                                                         ->  ok  [C9] …
indented code block                                                   ->  ok  [C9] …
```

- **The `gh:` exemption.** `gh:owner/repo` is copier's documented shorthand for a GitHub source. The template's own `VALIDATION_LOG.md:2075` records `copier copy gh:DuqueOM/ml-service-template /tmp/adopter` unpinned, and its ADR-030 cites `copier copy gh:org/repo svc/` as what adopters expect. Any such command with a local destination is classified as a local source, because "http" is absent, and is exempted. Unpinned, that command is the one C9 exists for: the docstring cites 582 files deleted upstream.
- **The `#` lead is confirmed.** A quoted `#` before the command cuts the command off the line.
- **Fences.** An info string outside `[a-z]*` desynchronises the fence pairing. C10's `_FENCED` already handles `~~~`, and C9 does not.
- **Tests.** Two new mutations survive the whole gate test file: **R14-C9-http-guard-dropped** and **R14-C9-fence-needs-language**. No test pins either the `http` guard or a fence with no language.

None of these forms occurs in the tree today.

**Fix:** classify the source by copier's own rules. The first positional argument after the subcommand is the source, and it is local only if it is a filesystem path, not `gh:`, `gl:`, `git@`, `git+…` or `https://`. Use `shlex.split` rather than a regex, so quoting is honoured and the comment is stripped by the tokenizer. Reuse C10's `_FENCED` for blocks, and treat 4-space-indented blocks as code too. Add the probes above as tests and catalogue entries.

### [P2-3] The artifact gate silently skips a reader line it cannot match, so a straddle can hide behind a name spelling or a missing pin

```text
scripts/check_artifact_compatibility.py:150   if name not in SEAM:                          # no PEP 503 normalisation
scripts/check_artifact_compatibility.py:166   if not versions or specifier is None: continue  # an unpinned reader is skipped

$ uv run python scripts/mutation_harness.py R14-artifact-reader-name-unnormalized R14-artifact-reader-unpinned
SURVIVED R14-artifact-reader-name-unnormalized      every command passed   <-- unexpected
SURVIVED R14-artifact-reader-unpinned               every command passed   <-- unexpected
```

- `scikit_learn ~= 1.5.0` in the container's requirements makes pip install scikit-learn 1.5 against training's 1.9.1. That is a real straddle. The gate exits 0 and the gate tests pass, because `scikit_learn` does not equal `"scikit-learn"`.
- Dropping joblib's pin (`joblib`) lets the container install any joblib, and the gate says nothing.

Either mistake can arrive in a `copier update`, which is exactly how the joblib straddle closed this round. The gate's docstring promises that a straddling SEAM package "fails the gate". This mutation shows it doesn't.

**Fix:** normalise names (`packaging.utils.canonicalize_name`) on both sides. Fail when a SEAM package has no specifier in the reader, or a specifier that admits more than one minor version. Keep both mutations in the catalogue.

### [P2-4] The scripts/ coverage figure, and the floor of 83 set on it, leave out two tracked scripts that never run

```text
pyproject.toml:180-191 ([tool.coverage.run]),  .github/workflows/ci.yml:376-379 (--cov=scripts … --cov-fail-under=83)

$ uv run pytest -o addopts="" -q --cov=scripts --cov-branch --cov-report=json:cov.json
TOTAL                                      3438    501   1452    188    84%
$ python3 - (compare cov.json files with git ls-files 'scripts/*.py')
tracked scripts py: 31  measured: 29  tracked-not-measured: ['scripts/datasets/fetch.py', 'scripts/local/preflight.py']
$ coverage.parser.PythonParser statement counts
scripts/datasets/fetch.py 210 statements
scripts/local/preflight.py 105 statements
{'covered_lines': 2937, 'num_statements': 3438, 'covered_branches': 1154, 'num_branches': 1452, 'percent_covered': 83.66…}
with 315 unmeasured statements at 0% (their branches ignored, so the true figure is lower still): 78.60%
```

Coverage reports a never-executed file only if it sits in a package, and `scripts/datasets/` and `scripts/local/` have no `__init__.py`. The published "scripts/ coverage" is therefore coverage of the scripts that some test happened to execute. 315 statements (8.4% of the measured 3,438) are invisible. Counted at 0%, which is the honest value for code no test runs, the figure is at most **78.60%**. That is below the floor of 83 and below the 80.20–80.82% the floor's own comment cites as the pre-#101 baseline. The number is measured correctly, and CI and a local run agree to two decimals. What it measures is not what "scripts/ coverage" says. Setting `include_namespace_packages` at report time does not help: the unexecuted files are never discovered.

The `patch = ["subprocess"]` lead itself is sound. Every counted file is under `scripts/`, nothing from a sandbox or `services/` is counted, and a leftover probe (`scripts/_clock_probe.py`) appears in the data but has no source, so it is not reported.

**Fix:** set `[tool.coverage.run] source = ["scripts"]` with `include_namespace_packages = true` in the **run** section, so coverage discovers them at measurement time (coverage ≥ 7.0). Alternatively, add `__init__.py` to the two directories. Re-measure, and set the floor from that figure. That would lower the literal, which `check_thresholds.py` rightly blocks, so it needs `--accept` with this finding as the reason. Or keep 83 and add tests for `fetch.py` and `preflight.py` first.

### [P3-2] The brief's instruction to extend the harness can't be followed without a commit, and the brief's count is stale

```text
scripts/mutation_harness.py:84-86 (refuses a dirty tree);  docs/governance/audit-brief.md:437 ("its 36 entries")

$ echo "# probe" >> tests/mutations.yaml && uv run python scripts/mutation_harness.py E1

Adding an entry to `tests/mutations.yaml` makes the tree dirty, so the harness refuses. Replace "36" with "run the harness", per the brief's own rule about restated numbers.

### [P3-3] `check_thresholds.py` falls back to the local `main` branch before the parent its comment promises

```text
scripts/check_thresholds.py:222   for default in ("origin/main", "main"):
scripts/check_thresholds.py:227   # … fall through to the parent.

$ uv run python scripts/check_thresholds.py            # worktree at f8b9d27 = origin/main
[thresholds] OK — 14 watched, none loosened against 7dfec654e1fd2da1942a5af89cf707792863e334
```

On a commit that is on `origin/main`, the merge base with `origin/main` is `HEAD`. The loop then tries the local `main`, which here is a stale branch 11 commits back, before the #102 ratchet, and compares against that. A later lowering from 83 to 80 on `main` would compare against the old 74 and pass locally. In CI, the local `main` ref is normally absent and `HEAD~1` is used, so this is a "green local run CI cannot reproduce" in reverse: the result depends on the state of the machine.

**Fix:** drop `"main"` from the loop, or use it only when `origin/main` does not exist. Make the fallback `HEAD~1` as the comment says.

### [P3-5] The service can't be regenerated from its own answers file: `service_name` is supplied by hand and never recorded
