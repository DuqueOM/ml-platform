open: every attribute of a `Threshold` (pattern, direction, rename factor) is editable in the same commit as

`re.search` takes the first match, so a comment or docstring can stand in for the constant.

merge-base `fbd1eb0`, and main resolves `HEAD~1`. But the env var is the documented PR-lane override.

with a scratch cwd, and it loaded at all 12 historical revisions of the file (7 to 29 definitions each).

- Anchor patterns at line start, `^NAME\s*=`, and fail on more than one match.

  "nothing to compare".
- Add a value assertion for `MIN_SKILL` and `MIN_COVERAGE` in `test_dags.py`.

`snapshots()` deliberately returns UTC-aware datetimes ("all of which is UTC"). A cutoff taken from it, or
from `datetime.now(UTC)`, raises.

**Fix:** convert the cutoff to naive UTC. Compare the snapshot id before and after, and return `None` (or
raise) when nothing committed. Add a filesystem-backend test covering the boundary, aware input and the
no-op.

#114 holds within the DAG: every read after ingest names one id. R16-DAG7, R16-DAG8 and R16-PER1 are all
killed by assertions, and `source_snapshot` equals what `fit_final` read.

But the id comes from `table.current_snapshot()` after `refresh()`, not from the commit this write made.
The DAG comment says "another writer — the KFP pipeline, a manual ingest — can commit between this task and
the next". It can also commit between `append`/`overwrite` and `refresh`, and then the run validates, trains
on and records the other writer's snapshot, including its rows.

lakehouse (it passes `dsl.Dataset` artifacts), so today the other writer would be a manual ingest.

**Fix:** take the snapshot from the transaction's own commit. In pyiceberg 0.12, run the write through
`table.transaction()` and read `txn.table_metadata.current_snapshot_id` before commit returns, or pick the
newest snapshot whose `parent_snapshot_id` equals the pre-write head. Assert it in a test that forces the
interleaving.
