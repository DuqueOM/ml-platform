```text

  $ THRESHOLD_BASELINE_REF=71528ad uv run python scripts/check_thresholds.py

```

#125 moved Python thresholds from `pattern` to `symbol`, read by value. The baseline loader still rebuilds each
baseline threshold from four fields, so a baseline that uses `symbol` comes back with `pattern=""`. That pattern
matches every line, and `read()` refuses it.

- **Why CI on 746d6d6 is green.** Its baseline was 71528ad, which predates `symbol`.
- **What happens next.** The next push to main compares against `HEAD~1` = 746d6d6, and a PR compares against
  its merge-base. Both crash. The gate fails closed, so nothing is loosened silently, but CI's "Thresholds" step
  and `make verify` go red for every change until this is fixed. The tempting response is to bypass a STOP gate.
- **What it does to the mutation evidence.** Six catalogue entries that edit `check_thresholds.py` are counted
  as killed by `test_the_working_tree_has_loosened_nothing` through this crash (blank `AssertionError` plus the
  traceback), not through the property each removes:
  - R14-thresholds-stale-local-main;
  - R15-TH2, R15-TH3;
  - R16-TH1;
  - R17-THR3, R17-THR4.

  So is my R18-PV1. Their kills say nothing about their targets until this is fixed.

**Fix:** serialise the whole `Threshold` (`dataclasses.asdict`, including `symbol` and `renamed_from`) in
`_DEFINITIONS` and rebuild it with `Threshold(**fields)`. Add a test that runs the gate with
`THRESHOLD_BASELINE_REF=HEAD` on a clean tree, so the current definitions are loaded as a baseline. Re-run the six
entries afterwards and classify their kills again.
