The sha-carrying path is sound. A marker moved to HEAD fails; an unreachable sha fails; an old audited sha is
counted honestly.

The date-only fallback is described as being "only for markers written before that convention existed". It
accepts any marker today. So one edited line — `Last independent audit: 2099-12-31` — keeps C7 green for every
future commit with nothing behind it in ops/audit.jsonl. That is the round-six failure this check was built to
make impossible.

**Merge-commit counting was also checked**, in a throwaway `git clone --no-local` under the scratchpad, with a
2-commit branch and main moved by one commit:

| Count | Value |
| --- | --- |
| branch | 12 |
| CI's synthetic merge ref | 13 |
| merge ref with merges included | 14 |
| main after the squash | 12 |

`--no-merges` does exclude the merge commit. Local and CI agree whenever the branch is up to date. The merge ref
adds only main's genuinely unreviewed commit. A multi-commit PR is charged per commit and drops back after the
squash, so a PR can be red at N while the squash lands green.

**Fix:**
- Refuse a marker without a sha once the trail exists. Every recorded round has one.
- Match the sha case-insensitively, or reject uppercase explicitly.
- Fail a marker dated after today, and after the trail entry it cites.
- Optionally require that the cited trail entry's `ts` is not before the marker date.

```text
  $ bash --noprofile --norc -eo pipefail s.sh; echo $?                              → 1     (GitHub's default)
  $ (instead: folded continuation `|| echo "bandit findings, see log; exit 1 is for main only"`, no shell override)
  555 passed; [actions] OK
  R19-BLK1, R19-BLK2: SURVIVED
```

This is the class of rounds 16–18 again, through two doors those fixes left open:
- **`shell:` is never read.** GitHub's default bash is `-eo pipefail`; `shell: bash {0}` drops both.
- **The `||` rule is a text search.** It treats any `exit [1-9]` later on the line as a failing branch, even
  inside a string.

The behavioural test runs only the first physical line of `run:`. A YAML plain-scalar continuation is joined by
the parser and invisible to the regex, so the test executes a command CI does not run.

The same `shell:` gap reaches every `run:`-based control: `uv lock --check` (P9), and P10's digest checks (P3-4).

**Fix:**
- Treat any `shell:` on a control's step, job or workflow `defaults.run` as non-blocking unless it is in an
  allowlist (`bash -eo pipefail {0}`).
- Judge `||` by parsing the branch: shlex the command list and require that the branch's last command is
  `exit N` with N ≥ 1, or `false`.
- Have the behavioural test run the *parsed* `run:` value through `bash -eo pipefail` (or the step's declared
  shell), not the first physical line.
- Add R19-BLK1 and R19-BLK2 to the catalogue.

The work order says quick-start commands "are denied by default: each passes only when a rule reads it and finds
what it runs pinned". `-r` is read as "a pinned requirements file" without opening it. The file may not exist,
may be outside the repository, and may hold `copier>=0`. After it, `provided` holds `*`, and every later program
— `eval`, `timeout`, anything on PATH — passes without its arguments being read. U8 shows the consequence: a
moving copier ref, which C9 exists to refuse, accepted.

The parser half of #125/32f6f39 holds (Verified working). The two repositories' `readme_standard.py` and
`readme-standard.md` are byte-identical, so the template inherits each of these.

**Fix:**
- Require `-r FILE` to name a file `repository.holds()`, and read it with the same `_requirement` rules.
- Replace `*` with the names that file installs.
- Treat `--with-requirements`, `--index-url`, `--extra-index-url`, `--find-links` and `--index` as read values:
  a URL is unpinned, and an index other than PyPI is refused.
- Make `timeout`, `xargs` and `eval` recurse like `env`/`sudo` do, or refuse them.
- Track `cd` and refuse relative paths after it.
